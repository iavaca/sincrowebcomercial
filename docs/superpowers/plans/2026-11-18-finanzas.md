# Finanzas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Página Finanzas del panel: cargar gastos, cobros y transferencias de Iván e Isabella y ver cuánto transfiere uno al otro para quedar 50/50.
**Architecture:** `/finanzas.html` + `public/finanzas.js` (render en cliente con textContent, sin innerHTML) contra `/api/finanzas` (GET JSON, POST agregar/borrar). Datos en `finanzas/movimientos.json` de la rama huérfana `finanzas` de iavaca/sincroweb-pedidos, escritos con Contents API y el token del usuario.
**Tech Stack:** TypeScript (Vercel functions, Node ESM, imports con `.js`), vitest, JS plano en el cliente.
**Spec:** docs/superpowers/specs/2026-11-18-finanzas-design.md

## Global Constraints
- Montos enteros en pesos, > 0 y ≤ 1.000.000.000. Fechas `YYYY-MM-DD`.
- Personas fijas: iavaca 100360837 → `ivan` "Iván"; 75735426 → `isabella` "Isabella".
- Imports relativos siempre con `.js`; constantes en TS (sin JSON imports ni fs en lib/api).
- POST exige `origenValido` y `content-type: application/json` como /api/accion.
- Nunca se loguean montos ni conceptos.

## Review Focus
- Dos cargas simultáneas: PUT con sha viejo (409) → releer y reintentar una vez; si vuelve a fallar → 409 `conflicto`.
- Rama `finanzas` inexistente (primera carga) → GET devuelve lista vacía; POST crea la rama huérfana con `vercel.json` (deploys apagados) y el archivo.
- Archivo corrupto o con movimientos inválidos → 502, nunca se pisa.
- Borrar un id que no existe → 404 `no_existe` sin escribir.
- Usuario sin permiso de escritura en sincroweb-pedidos (403) → `github_sin_permiso`.

### Task 1: Dominio (lib/finanzas.ts)
**Files:** Create `lib/finanzas.ts`, Test `test/finanzas.test.ts`
**Produces:**
- `type Persona = "ivan" | "isabella"`; `PERSONAS: Record<Persona, {uid:number; nombre:string}>`; `personaDeUid(uid:number): Persona | null`
- `CLIENTES: {slug,nombre}[]` (los 13 de sincroweb-pedidos/lib/clientes.ts + `{slug:"otro",nombre:"Otro"}`), `CATEGORIAS = ["Hosting y servidores","Dominios","Software y suscripciones","Publicidad","Otros"]`
- `type Movimiento = {id:string; tipo:"gasto"|"cobro"|"transferencia"; fecha:string; monto:number; persona:Persona; para?:Persona; cliente?:string; clienteNombre?:string; categoria?:string; concepto:string; cargadoPor:Persona; cargadoEn:string}`
- `validarNuevo(body:unknown, cargadoPor:Persona, ahora:Date, id:string): {ok:true; mov:Movimiento} | {ok:false}` — cobro exige cliente válido (si "otro", clienteNombre 1–80 chars); gasto exige categoría válida, cliente opcional; transferencia exige `para` ≠ persona; concepto 0–200 chars (obligatorio 1+ en gasto).
- `parsearArchivo(texto:string): Movimiento[]` (lanza si no es `{version:1, movimientos:[...]}` válido)
- `calcularSaldo(movs): {cobros; gastos; ganancia; mitad; neto:Record<Persona,number>; transferir:{de:Persona; para:Persona; monto:number}|null}` — neto = cobrado − gastado + transferido − recibido; diferencia = neto.ivan − mitad; >0 → ivan→isabella; redondeo a entero (Math.round del medio peso).
- [ ] Tests: saldo vacío → null; Iván cobra 100000 y Isabella gasta 20000 → ganancia 80000, Iván transfiere 60000; tras registrar esa transferencia → null; validaciones rechazan monto 0, decimal, tipo desconocido, transferencia a uno mismo, cliente inexistente.
- [ ] Implementar, correr `npx vitest run test/finanzas.test.ts`, commit.

### Task 2: Almacén y API (lib/almacen-finanzas.ts, api/finanzas.ts)
**Consumes:** Task 1, `llamarGitHub`, sesión como api/accion.ts.
**Produces:** `GET /api/finanzas` → `{yo:Persona, personas, clientes, categorias, movimientos (orden fecha desc), saldo}`; `POST /api/finanzas` `{op:"agregar", movimiento:{...}}` | `{op:"borrar", id}` → `{ok:true}` | `{ok:false, motivo, texto}`.
- `leer(token): {movs, sha:string|null, rama:boolean}`: GET `/repos/iavaca/sincroweb-pedidos/contents/finanzas/movimientos.json?ref=finanzas`; 404 → vacío.
- `guardar(token, movs, sha|null, rama:boolean, mensaje)`: con rama → PUT contents (branch finanzas, sha); sin rama → POST git/trees (archivo + `vercel.json` `{"git":{"deploymentEnabled":false}}`), POST git/commits sin parents, POST git/refs `refs/heads/finanzas`.
- Mensaje de commit: `Finanzas: <agrega|borra> <tipo> (<persona>)`.
- [ ] Tests con fetch mockeado (patrón test/accion.test.ts): GET vacío con 404; agregar crea rama; agregar con rama hace PUT con sha; 409 → reintenta una vez; borrar id inexistente → 404; origen inválido → 403; uid no persona → 403; 403 de GitHub → github_sin_permiso.
- [ ] Implementar, correr tests, commit.
